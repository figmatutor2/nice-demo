# Goal 루프 — 측정 → 수정 → 재측정

완료 조건: **$ARGUMENTS**

이 조건을 **측정 가능한 숫자**로 만들고, 그 숫자가 목표에 도달할 때까지
`[측정 → 수정 → 재측정]`을 반복한다. 이것은 CLAUDE.md 4원칙의
**Goal-Driven Execution**을 실행하는 루프다 — 자체 검증(숫자)이 목표를 통과하기 전에는
"완료"라고 말하지 않는다.

## 규칙

1. **측정 우선 (Think Before Coding).**
   먼저 현재 위반/에러 수를 측정해 기준선(0회차)을 잡는다. 측정 없이 수정부터 하지 않는다.

2. **측정은 스크립트로, 숫자로 판정.**
   완료 조건에 맞는 측정 명령을 골라 실행하고 **정수 하나**로 환산한다.
   - **하드코딩 검사** → 아래 "하드코딩 측정 스니펫"을 **그대로 재사용**한다
     (`.claude/hooks/check-hardcode.mjs`를 각 소스 파일에 합성 payload로 먹여 위반 수 집계).
   - **타입 에러** → `npx tsc --noEmit 2>&1 | grep -cE 'error TS'`
   - **빌드** → `npm run build` (성공=0, 실패=1)
   - **린트/테스트** → 프로젝트에 있으면 해당 명령의 실패 건수.
   - 스크립트로 측정 불가한 조건이면 그 사실을 명시하고, 수동 판정 기준을 먼저 합의한다
     (추측으로 "됐다"고 하지 않는다).

3. **수정은 surgical.**
   측정으로 드러난 위반만 고친다. 요청 범위 밖 리팩터·포맷팅을 섞지 않는다.
   토큰 관련 위반은 값을 `src/tokens/*.tokens.css` 토큰으로 매핑하거나 기존 토큰 유틸리티로 교체한다.

4. **매 반복 진행 로그 (필수).**
   각 회차 끝에 정확히 이 형식으로 한 줄 출력한다:
   ```
   N회차: 남은 위반 X건
   ```
   (0회차 = 기준선. 조건이 "에러"면 "위반"을 맥락에 맞게 쓰되 숫자·형식은 유지.)

5. **정지 조건.**
   - **성공:** 숫자가 목표(보통 0)에 도달 → 최종 숫자와 함께 완료 보고.
   - **정체:** **연속 5회** 반복해도 숫자가 줄지 않으면(진전 없음) 중단하고
     현황 보고: 남은 위반 목록, 왜 막혔는지, 다음 선택지. 무한 반복 금지.

## 하드코딩 측정 스니펫 (재사용)

완료 조건이 하드코딩/토큰 관련이면 이 명령으로 위반 수를 집계한다. `.claude/hooks/check-hardcode.mjs`를
그대로 재사용하므로 hook과 판정 기준이 100% 일치한다.

```bash
total=0
for f in $(git ls-files 'src/**/*.ts' 'src/**/*.tsx' 'src/**/*.js' 'src/**/*.jsx' 'src/**/*.css'); do
  n=$(jq -n --arg p "$f" --rawfile c "$f" '{tool_input:{file_path:$p,content:$c}}' \
        | node .claude/hooks/check-hardcode.mjs 2>&1 \
        | grep -cE '^[[:space:]]+L[0-9]+')
  total=$((total + n))
done
echo "남은 위반: ${total}건"
```

토큰 파일(`*.tokens.css`)과 예외 줄(`token-exempt:`)은 hook이 알아서 제외한다.
파일별로 어디가 위반인지 보려면 위 루프에서 파일명과 함께 stderr 전체를 출력하면 된다.

## 절차

0. **기준선 측정** → `0회차: 남은 위반 X건` 출력.
1. X가 목표면 즉시 완료 보고하고 종료.
2. 아니면 위반 항목을 찾아 surgical하게 수정.
3. **재측정** → `N회차: 남은 위반 X건` 출력.
4. 줄었으면 정체 카운터 리셋, 안 줄었으면 +1.
5. 목표 도달 → 완료 / 정체 5회 → 중단 보고 / 그 외 → 2로 반복.
